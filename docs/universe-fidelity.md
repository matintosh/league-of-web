## Method

**HYBRID (real styles + visual ref) — see docs/reference/components/README.md.** For EVERY component: (1) extract the REAL live-site computed styles/DOM/hover with `node scripts/extract_styles.mjs <live-url> --anchor "<text>" --hover` and build to those exact values (map colours→--color-* tokens; add a token if none); (2) confirm LAYOUT + VARIANT against the reference screenshot + annotated crop (docs/reference/components/); (3) measure our /showcase/<slug> and diff. Real values win for styling, ref wins for layout/variant. Screenshot-only matching is NOT sufficient — it marked things 'converged' that had wrong colours, wrong alignment, missing crest/hover, and the wrong variant.

Original method (still applies for discovery/build routing): 
Same loop as launcher/login/client: **discover** visual deltas vs the `docs/reference/universe-*.png`
references, **build-loop (:11)** builds from `universe,status:ready` issues. Lightweight
source-aware production diff (Read component source for real selectors → measure
`/showcase/<slug>` on prod → compare to ref → file measured deltas or DRY). Tokens-only.

## Palette / tokens

Reuse Hextech gold tokens (`gold-1..5`, `text-gold-1`, `font-display`). Add `--color-universe-*`
in `packages/tokens/src/theme.css` as sampled (bg near-black ~#0a0a0e, card surface ~#111015,
hairline gold). NO raw hex outside tokens.
